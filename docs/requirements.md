# MdbHub 요구사항

## 배경
사양(spec)을 Access `.mdb`로 관리 중이며, 수작업으로 인한 휴먼에러가 많아 통합 툴로 대체한다.

## 용어 / 데이터 규칙
- **약액코드**: `CHEMICAL_NO` + `SUB_CHEMICAL_NO` 조합. 추출 단위.
- 대부분의 테이블에 `CHEMICAL_NO`, `SUB_CHEMICAL_NO`, `NUM`이 있고, 이 3개 조합이 **PK**.
- 일부 테이블은 이 컬럼이 없을 수 있음 ("대부분"이므로 예외 테이블 처리 방식은 확인 필요).
- 규모: mdb당 테이블 약 15개, 행 수 = 테이블별 고정 개수 × 약액 개수. 최대 약 15만 행.
- 환경: 64비트 (ACE OLEDB 64비트 드라이버 필요).

## 추출 필터 방식
- 약액코드는 행마다 존재하며, 사용자는 보통 약액코드로 필터링해 해당 약액의 행을 쭉 확인한다.
- 추출 기준은 기본이 CHEMICAL_NO, SUB_CHEMICAL_NO이지만, **사용자가 컬럼과 값을 자유롭게 선택**해 단순 필터링으로 추출할 수 있어야 한다.
- 필터 컬럼이 없는 테이블은 추출 대상에서 **제외**한다.

## 핵심 작업
1. **추출**: 사용자가 지정한 필터 조건을 만족하는 행을 모든 테이블에서 추출해 새 mdb로 생성.
2. **반영(덮어쓰기/삽입)**: 추출된 행 또는 삽입할 행만 모은 mdb를 다른 mdb에 반영. PK(CHEMICAL_NO, SUB_CHEMICAL_NO, NUM) 일치 시 덮어쓰기, 없으면 삽입.
3. **비교**: 서로 다른 mdb 파일의 같은 테이블을 PK 기준으로 비교(추가/삭제/변경/동일).

## 안전장치
- 반영(쓰기) 전 **자동 백업을 기본값**으로 수행.
- (제안) 반영 전 변경 미리보기, 트랜잭션으로 전체 성공/실패 처리.

## 구현 현황 (Data/Core 계층, 화면은 아직 없음)
- 완료: 스키마 읽기/검증, 필터 추출, 백업, PK 기준 비교, 반영(Preview/Apply: Upsert·InsertOnly, 백업+트랜잭션 롤백)
- 예정: WPF 화면(파일 열기, 컬럼별 체크 필터, 추출, 비교 diff, 반영 미리보기), 15만 행 성능 측정

## 기술 스택
- WPF (.NET 10), Telerik UI for WPF 2025.3.813 (라이선스 범위: 2025 Q3까지)
- Access 접근: System.Data.OleDb (64비트 ACE)
- 구조: MdbHub.Core / MdbHub.Data / MdbHub.App / MdbHub.Tests

## 결정 사항
- 비교 결과는 **화면에서 diff 표시**.
- 비교/반영 대상 두 mdb의 **스키마가 다르면 열리지 않게(거부)** 한다.
- Office는 64비트.

## 미정 사항 (확인 필요)
- 필터 UI 세부: 컬럼별 다중 값 선택(Excel 필터 형태) vs 조건식 입력
- 스키마 "같음"의 기준: 테이블/컬럼 이름·타입·PK까지 볼지
